# 在 Wiki 下创建问题表

使用 `create-lark-table <Wiki 父页面 URL>`，或用户明确要求在指定 Wiki 下创建问题表时执行。只创建新资源，不修改父页面正文、源模板或已有问题表。

## 1. 核对输入

1. 必须且只能得到一个 **HTTPS 飞书/Lark Wiki 父页面 URL**（`/wiki/<token>`）。允许参数用引号包裹；不支持云盘文件夹、未挂载 Wiki 的普通文档或额外参数。
2. 缺 URL 时询问用户；格式不支持时说明用法并停止。最终严格校验交给创建脚本。
3. 在创建前简短告知将开始建表；不要先扫描旧问题、重抓在线模板，也不需要提前单独运行 `check-lark`。

## 2. 只运行一次创建脚本

将 `<lark-dir>` 替换为本 Skill 的 `integrations/lark` 绝对路径，安全引用 URL：

```bash
node --experimental-strip-types "<lark-dir>/scripts/create.ts" '<Wiki 父页面 URL>'
```

使用 Node.js >= 22.19.0、官方 `lark-cli --as user` 和用户身份授权。不要把 URL 或其他用户文本直接拼进未引用的 shell 命令；不要将 `/gkd-workloop` 当作 shell 命令。

脚本读取本地 `assets/issue-tracker.json`，依次解析 Wiki 父节点、创建独立 Base、挂载到父节点、配置默认 grid 与三个视图、核对字段及挂载关系，并添加一条“待确认”且**未交付 AI** 的示例数据。不要另起子 Agent 或模型重复创建步骤。

## 3. 核对结果并关联项目

1. 仅当进程退出码为 `0` 且返回 `status=created` 时，判定建表成功。
2. 使用创建结果中的 `baseToken` 和 `tableId`，按 [项目绑定](bindings.md#创建后绑定项目) 核对当前工作区与项目。归属明确且用户未要求仅临时使用时，通过 `scripts/bindings.ts` 保存关联。
3. 反馈首行为 `已创建漏洞跟踪记录：<返回的 url>`，使用真实创建链接，不附加侧边栏隐藏参数。绑定成功则补充关联结果；未绑定则说明原因及下一步。不要输出内部 JSON。
4. **建表成功但绑定失败**：保留创建成功结果，标明“表已创建，绑定未完成”。不重跑创建脚本，也不删除新表。

## 4. 失败或结果未知时

- 缺少 CLI：提示安装并配置 PATH。遇到 scope、登录或 ACL 错误时按实际 CLI 提示和授权帮助处理；不能切换 bot 身份、偷偷加入 `--yes` 或把旧预检缓存当作创建权限。
- 创建失败、超时、挂载未就绪或部分成功：停止后续写入并核对可能已经创建的资源。不自动重试、删除、回滚或重复添加示例。
- 用户中断时终止运行中的脚本，并核对已经生效的外部写入；恢复只继续可安全确认的未完成步骤。

## 本地模板

`assets/issue-tracker.json` 是字段、选项、颜色、视图和示例数据的唯一结构来源。模板于 2026-11-11 从指定[漏洞跟踪记录](https://pcn60j63v4en.feishu.cn/wiki/H5WZweD3PiUgV7k2AYtcD6otnUf?table=tbl0FJQqsZukRZiY&view=vewLgt4u2h)只读提取；运行时不访问该源表，也不保存真实问题、附件、账号或旧资源 ID。

新资源统一命名“漏洞跟踪记录”，是挂在 Wiki 父节点下的独立多维表格，不复刻原电子表格容器或表单。只保留一条虚构示例；无需在成功反馈中逐项解释模板差异。
