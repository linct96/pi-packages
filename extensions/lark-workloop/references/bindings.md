# 问题表与本地项目绑定

当 create 成功返回真实表身份、work 已解析真实问题表，或用户用自然语言要求查看、修改、移除绑定时，加载本参考。归属判断由当前主 Agent 完成；`scripts/bindings.ts` 只负责本地存储，不访问飞书、不修改业务代码、不验证模型的推断是否正确。

## 文件与身份

绑定自动保存在 `${PI_CODING_AGENT_DIR:-~/.pi/agent}/lark-workloop/workspace-bindings.json`，与授权检查缓存分开，`check --invalidate` 不清除绑定。不存在时读取为空且不创建文件；首次核实保存后自动生成，不要求用户先手工配置。

- 表身份是解析后的 `baseToken + tableId`。Wiki token 只是入口，Wiki 指向 sheet 内嵌 Base 时必须解析到底层真实表；不能直接用 Wiki token 代替 Base token。
- view 只限制本轮范围，不作为长期绑定键，不因切换视图创建新绑定或扩大处理范围。
- 每条关联有稳定 `id`，包括绝对真实 `workspace`、工作区内相对 `project`（普通仓库为 `.`）、`source`（`inferred` 或 `user`）、简短 `evidence` 及自动更新时间。
- 同一张表可对应多个子项目或多个工作区。新增关联不删除旧关联；不得因为处理了后一条问题就覆盖前一条的项目归属。
- 不保存凭据、访问令牌、授权链接、完整问题正文或完整日志；依据只记录必要的项目文件、模块及核实结论。此文件是项目记忆，不是问题领取锁、代码执行权限或验收记录。

## 创建后的归属判断

建表与项目关联是独立结果。仅在创建脚本退出码为 0 且 `status=created` 后尝试绑定；失败、部分成功或结果不明时不凭已知链接猜表身份，也不为补绑定重跑 create。

1. 直接使用创建结果中的 `baseToken`、`tableId`，无需再访问飞书解析链接或读取示例问题。以当前 Agent 会话 cwd（快捷入口提供的 cwd 优先）为默认工作区，核实真实目录；不是技能安装目录，不扩大到 cwd 外的仓库根，不跨符号链接边界。用户已明确指定项目时以该意图核实；声明仅本次使用或不要保存时不持久化。
2. 由当前主 Agent 只读必要的适用 AGENTS.md、README、workspace/package 配置及相关代码，结合本次创建意图判断项目归属。普通单项目仓库可记录 `project: "."`；monorepo 应定位真实子项目，不能仅因 cwd 是仓库根就绑定根目录，也不能把示例数据当作真实项目证据。该步骤不领取问题、不修改业务代码、不安装依赖或执行项目测试。
3. 归属明确时按下文脚本协议先 read，再携 `expectedRevision` 保存，依据只记录必要文件和归属结论。自动推断使用 `source: "inferred"`；用户明确指定或确认的归属使用 `source: "user"`。沿用多关联、冲突与用户确认保护，不覆盖旧关联或把 user 降为 inferred；后续 work 仍结合具体问题核实，可补充其他子项目。
4. 当前目录不是可识别项目、证据不足、存在多个无法区分的候选或绑定冲突时，不保存猜测，告知表已创建并及时询问具体归属；用户可暂不绑定，留到 work 再核实。绑定读取或保存失败时，保留新表并报告“表已创建，绑定未完成”及原因、下一步；不声称已记住，不重新建表。后续获确认或恢复时只继续未完成的绑定步骤。

## work 的默认目录与复用

1. 显式 `--workspace` 优先用于本轮，未指定时使用当前 Agent 会话 cwd（快捷入口附带的当前会话 cwd 优先），不是上次 Bash `cd` 的目录，也不是本技能安装位置。
2. 将本轮目录解析为真实目录，作为修改边界；然后以真实表身份读取已存关联。只复用实际项目路径仍存在、位于本轮工作区内且适用于本条问题的关联。当前 cwd 本身位于旧关联的子项目时，可以复用该项目线索，但不能将修改边界扩大到旧仓库根。
3. 若同表只绑定到另一个工作区，不静默跳到外部目录执行，也不自动把绑定改成本次 cwd。说明差异，请用户确认是临时在当前目录执行、切换到原工作区，还是永久更换绑定。
4. 匹配多个子项目时逐条结合问题和代码选择；如果无法区分就及时询问，不能默认取第一项。已存绑定失效或目录不存在时也须重新核实，不创建目录、不盲目恢复旧路径。
5. 显式参数只是本次执行范围，不代表永久改绑。临时指定不能无条件覆盖长期记录；用户说明“仅本次使用”时不保存新关联。没有冲突且未声明仅临时时，可在核实后自动新增关联；更换旧绑定仍需迁移证据或用户确认，不能因参数变化直接覆盖。

## 推断、记录与更新

- 无绑定或新增问题涉及未记录模块时，读取工作区内的 AGENTS.md、README、workspace/package 配置和相关代码，根据问题、调用链及可验证行为定位项目；monorepo 应记录真实子项目，例如 `apps/web`，不能仅因 cwd 是仓库根就保存 `project: "."`。
- 核实问题与项目的对应关系后自动保存，无需每次要求用户重复确认。依据应能指向真实文件/模块；可以在根因定位或修复阶段保存，最终有新证据时再更新。不需要等同于人工验收通过，也不记录未经验证的猜测。
- 实在无法自动推断、证据不足、多个候选冲突或需要越出工作区时，及时向用户发起具体确认提问；确认前不修改对应业务代码、不持久化该推断。用户明确确认的归属使用 `source: "user"`，不能被后续模糊推断轻易替换。
- 自动发现新的、已核实子项目时新增关联，保留其他项目。只有明确的迁移/归属变更证据足以排除旧关联，或用户明确要求更换时，才用旧 `id` 更新原关联；证据与旧记录冲突而无法消解时先询问。更新后简短告知“已记录/更新绑定：表 → 工作区 → 子项目”，不只在内存记住。
- “把这张表改绑到 apps/admin”“这个工作区路径已经搬家了”“查看/移除这条绑定”等是自然语言绑定管理。只做必要的链接解析、目录核实和本地存储，不因此领取问题、改业务代码或写飞书；删除前需明确具体关联，不能删除同表所有项目。仅要求解释或预览则只读，不保存。
- 读取损坏或保存失败时说明原因和恢复动作，不假装已记住。尚未改代码时暂停对应处理；已产生改动时保留并报告，不重做修复来重试保存。

## 本地脚本协议

使用 Node.js >= 22.19.0。通过 stdin 传 JSON，不将问题正文拼进 shell，不直接用 edit/write 覆盖绑定文件。以下 `<skill-dir>` 是技能真实目录：

```bash
node --experimental-strip-types "<skill-dir>/scripts/bindings.ts" <<'JSON'
{"action":"read"}
JSON
```

成功输出 `status: "ready"`、`version: 1`、`bindings` 和文件内容摘要 `revision`。绑定只按结构读取；复用前仍由 Agent 核实当前目录和实际归属，不能因脚本读取成功就信任所有路径。

保存前先 read，依据返回值构造一个关联，传入本次 `expectedRevision`：

```json
{
  "action": "save",
  "expectedRevision": "<本次read返回的revision>",
  "binding": {
    "baseToken": "<已解析的真实Base token>",
    "tableId": "<已解析的真实table_id>",
    "workspace": "/absolute/repository",
    "project": "apps/web",
    "source": "inferred",
    "evidence": "apps/web/package.json 与 src/pages/issues 中的实际实现确认了问题归属"
  }
}
```

- 修改已有关联时在 `binding` 中带原 `id`，只能修改该关联；不能把一个表的 id 用来更换成另一张表。新增时省略 id，同表同工作区同项目会更新原关联而不是重复添加；同表其他项目仍保留。
- 存储层拒绝以 `source: "inferred"` 覆盖已有 `source: "user"` 的关联（同键保存和按 id 更新均受保护）。归属确实变化时先取得用户确认，再以 `source: "user"` 更新；自动推断不能降低人工确认的优先级。
- 移除时传 `{"action":"remove","id":"<明确选中的关联id>","expectedRevision":"<本次revision>"}`。目录已失效的关联也可明确移除，不以删除记录为由访问旧目录。
- `workspace` 必须是已存在的绝对目录，`project` 是相对目录，省略时为 `.`。保存时解析真实路径并拒绝 `..`、绝对项目路径、文件和符号链接越界；保存后的路径为规范化结果。
- 保存/移除成功分别返回 `status: "saved" / "removed"` 及最新 revision、完整关联列表。串行处理，一次只提交一个核实后的关联；下一次写入使用最新 revision。
- 脚本用排他锁、旧版本比较及同目录临时文件 rename 保存（文件权限 0600），避免其他脚本写入丢失。冲突时重新读取并重新判断，不能只替换 revision 后原样重试。
- 错误输出 `status: "error"`，进程非零退出；先核对真实文件和目标状态，不把计划中的保存当作成功。文件损坏/版本不兼容时保留原文件，不清空或覆盖为默认配置。异常退出遗留 `workspace-bindings.json.lock` 时，先确认没有活跃写入，再请用户处理，不自动删锁抢占。不要混用外部编辑器并发写入此文件。

脚本只能验证本地结构、路径和版本，不能证明表真实存在或依据可信，也不限制宿主工具权限；这些语义判断与授权仍由主 Agent 承担。
