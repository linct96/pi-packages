# create：创建漏洞跟踪记录

用法：`/lark-workloop create <Wiki 父页面 URL>`。这是创建新资源及在归属明确时记录本地项目关联的授权；不改父页面正文，不改源模板或已有表。只支持 HTTPS 飞书/Lark `/wiki/<token>` 父页面，不接受云盘文件夹或未挂载 Wiki 的普通文档。

## 执行

显式快捷命令转发到本 Skill，与原生 skill、自然语言创建使用同一流程，由当前主 Agent 指导并调用现有脚本。

先校验参数：必须且只能提供一个 Wiki 父页面 URL，允许用引号包裹；缺少时先询问，额外参数或不支持的链接先报告用法并停止，不执行脚本。URL 的严格校验仍由脚本负责。参数齐备后，先简短告知正在创建，再仅执行一次以下脚本（路径相对本技能目录；使用工具参数或安全 shell 引用传入 URL）：

```bash
node --experimental-strip-types <技能目录>/scripts/create.ts '<Wiki 父页面 URL>'
```

不要把 URL 拼成未引用的 shell 文本，不将 `/lark-workloop` 当 shell 命令。无需预跑 check、读取问题记录或再抓远端模板；不启动其他模型或子 agent。

脚本读取 `assets/issue-tracker.json`，显式使用 `lark-cli --as user`：解析父节点 → 创建带字段的空 Base → 挂到父节点下 → 复用新表默认 grid 并配置三个视图 → 核对字段与父节点 → 添加一条待确认分组的示例数据。输出只包含创建状态和新资源坐标，不回传原始 CLI 数据。

成功判据为退出码 0 且 `status=created`。建表成功后，加载 [项目关联](bindings.md) 的“创建后的归属判断”，由当前主 Agent 使用返回的 `baseToken`、`tableId` 和当前会话目录推断项目，通过 `scripts/bindings.ts` 记录；不把推断逻辑放进 `create.ts`，不需要等到首次 work 或存在真实问题。

反馈首行为 `已创建漏洞跟踪记录：<返回的 url>`，返回原始新建资源链接，不附加侧边栏隐藏参数；绑定保存成功再简短说明关联，未保存则说明原因、下一步或提出具体确认问题。不展示 JSON 或内部元数据。绑定失败不改变建表成功的事实；保留并报告已创建链接，不重跑创建脚本，不删除或回滚新表。

建表失败或会话变化立即停止，不自动回滚、删除或重新创建。CLI 写入可能部分成功或超时后已生效；保留并展示已知资源链接，先核对再决定如何补完，不能把整个 create 当成可安全重试的幂等操作。挂载未就绪不继续配置或声称完成。

缺少 CLI 时提示安装；遇到授权、scope 或 ACL 问题时按 `lark-shared` 修复，不能切换 bot、自动追加 `--yes` 或用旧 check 缓存推断有创建权限。创建权限按实际 CLI 错误补齐，不扩大 check 的基础权限集。

## 本地模板

提炼自用户指定的[漏洞跟踪记录](https://pcn60j63v4en.feishu.cn/wiki/H5WZweD3PiUgV7k2AYtcD6otnUf?table=tbl0FJQqsZukRZiY&view=vewLgt4u2h)，于 2026-11-11 通过 CLI 只读提取结构。运行时不依赖源页面或其权限，资产不保存账号、真实漏洞、附件或旧资源 ID。

- 仅包含一条虚构示例，分组为“待确认”，类型和当前状态留空、优先级 P1，未交付于 AI；描述和备注明确标注示例，可修改或删除，不复制源表真实记录或附件。
- 主字段：问题描述（文本）。其余字段：分组、类型、log/截图、优先级、是否交付于AI、当前状态、备注说明。
- 分组：待确认 / 处理池 / 需要决策 / 已归档；类型：BUG / 优化 / 需求；优先级：P0 / P1 / P2，默认 P1；当前状态为多选：待复现 / 待处理 / 已修复。保留源选项颜色，不额外添加选项或默认值。
- 漏洞分类（grid，按分组升序）、优先级看板（kanban，按优先级升序）、所有记录（grid，无分组），保留各视图可见字段顺序。
- 新表与表名统一为“漏洞跟踪记录”，不沿用无业务意义的源表内部名 `Table 1`。

边界：源文档为旧电子表格内嵌多维表格；新建为独立多维表格 Wiki 子页面，不复刻旧 sheet 容器。不创建或复刻源表单。这些差异仅保留在本文档中，不追加到成功反馈。
