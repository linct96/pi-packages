# 飞书多维表格工作流

创建问题表 → 录入问题并交付给 AI → 确认类型与状态、处理并及时回写 → 人工验收。

已有问题表可直接处理。创建成功后会尝试推断并记录项目关联，处理时仍会核实和补充，无需提前手工配置；未指定工作区时，使用当前会话的工作目录。

## 使用方法

1. **确定要做的事**：创建问题表、处理问题、管理项目关联，或了解使用方法。只咨询时说明步骤，不执行操作。
2. **读取对应说明**：只加载本次需要的参考文件，路径相对本技能目录。

   | 操作         | 命令或说法                                                               | 参考                               |
   | ------------ | ------------------------------------------------------------------------ | ---------------------------------- |
   | 创建问题表   | `create <URL>`，URL 为 Wiki 父页面链接                                   | [建表](references/create.md)       |
   | 处理问题     | `work --larkurl <问题表URL> [--workspace <工作区路径>]`                  | [问题处理](references/workflow.md) |
   | 管理项目关联 | “查看这张表关联的项目”“改绑到 apps/admin”“移除这条关联”                  | [项目关联](references/bindings.md) |
   | 检查执行环境 | `check`；强制复检用 `check --force`；清除检查缓存用 `check --invalidate` | [环境检查](references/check.md)    |

3. **按说明执行**：遵循对应文件的参数、权限、操作步骤和反馈要求。处理问题所需的环境检查与项目关联，按问题处理流程加载，不提前作为所有操作的前置步骤。

真实飞书操作依赖 `lark-cli`；Base、Wiki、旧电子表格和授权操作按需读取 `lark-base`、`lark-wiki`、`lark-sheets`、`lark-shared`。对应 CLI Skill 不可用时先查 CLI 官方帮助；无法确认命令和结果格式则暂停，不猜测操作。

命令前加 `/lark-workloop` 即可使用，也可以直接用自然语言提出需求，例如：“处理这张问题表中的问题，项目在当前目录。” 项目关联只管理本地关联，不启动修复或写入飞书。

只输入 `/lark-workloop` 且未说明需求时，回复以下两行，不启动流程：

```text
飞书多维表格工作流：建表 → 交付问题给 AI → 处理并回写 → 人工验收。
建表：/lark-workloop create <Wiki父页面URL>；处理：/lark-workloop work --larkurl <问题表URL> [--workspace <工作区路径>]
```

## 执行约定

- 只执行本次明确要求的操作；咨询、预览、引用命令或“先别处理”都不是执行请求。当前目录和历史任务也不代表执行请求。确定操作前，不检查环境、读取授权缓存、访问飞书或业务项目，也不修改文件。
- 执行前核对完整请求。缺少参数、参数不支持、目标不明或步骤冲突时先询问，不先执行其中一部分；信息齐备后直接执行，无需重复输入命令或确认，对应流程的风险确认仍保留。
- 目前只支持单轮处理，不支持持续监听、自动多轮、`watch` 或 `--watch`；遇到这类请求说明限制，不改成单轮执行或自行轮询。每轮在扫描筛选、排序后按描述复杂度限定任务数量，处理前告知预计数量；未选中任务延期到下次调用，不自动开启下一批，具体预算见问题处理说明。
- 多项操作先简短列出顺序，再串行执行。失败或等待用户时暂停后续步骤；用户明确继续后，从未完成步骤恢复，不重新执行已完成步骤。会话变化或结果不明时先核对并询问，不自动恢复。
- 在当前会话直接执行，不另启 Agent、模型、会话或后台任务；不把快捷命令或自然语言当作 shell 命令执行。

## 结果反馈

按对应流程简短反馈真实结果，不复述内部执行过程。当前会话元数据只用于确定执行目录，不回显上下文标签或原始 JSON。多项操作结束后，说明已完成、未完成及需要用户处理的事项。

遇到问题时，用“状态与原因 → 下一步”反馈：尚未执行为“未开始”，执行失败为“未完成”，等待补充或授权为“已暂停”。不展示凭据、堆栈、原始 JSON 或 CLI 诊断。

已创建的资源和已完成的改动应保留并告知用户。创建或写入结果不明时先核对，不自动回滚、重复写入或建议重跑整条命令。
